# Smart Crossfade stages

1. Analysis foundation: implemented as an opt-in Analyze Rhythm action in a song's Get Info sheet. A separate utility-priority decoder computes an energy-onset tempo estimate (60–180 BPM), observed beat positions, and half-second RMS bins. A single analysis lane avoids competing analysis decoders. Closing the sheet cancels its request. A versioned private cache uses path, size and modification time; changed files are rejected before publishing results. Cache writes are optional and retention is bounded to 256 entries. Songs over 15 minutes or jobs exceeding their decoding budget are rejected rather than silently sampling part of the song.
2. Transition planner: implemented as an analysis-only policy and a Preview Next Transition button in Get Info for the current queued library song. It tries 16/8/4-beat windows up to the requested length, requires strong profiles and steady local beats, limits cumulative relative beat drift to 70 ms, and bounds overlaps to 2–12 seconds. Incoming audio always starts at zero; its first detected beat is aligned by positioning the outgoing transition. Current playback position is a lower bound on scheduling. Consecutive tracks within the same album/disc remain gapless. Missing or uncertain analysis and incompatible beats produce a short 0.5–2 second track-length-scaled fallback; invalid timing, very short tracks, or missed windows remain gapless. Energy is only a candidate ranking hint, not a vocal detector. Live opt-in mixing is available in build 240; the preview itself never changes playback.
3. Two-stream PCM mixing: producer-side core implemented in CrossfadePCMReader. Two independent decoders feed a preallocated interleaved Float32 output, with sample-count-based fades and phase-boundary-aware reads. Equal-power mode reserves −3.01 dB headroom for dry and mixed PCM; equal-gain mode uses complementary cosine-squared gains. Packed integer and float PCM conversion is supported, with nonfinite sample sanitization. Source failure publishes no partially mixed block and requires an explicit reset. Seeking supports dry, overlap, and incoming phases. The raw mixer requires matching sample rates/channel counts. ConvertedPCMDecoder now explicitly resamples either source to a common interleaved Float32 rate using AVAudioConverter on the producer worker, retaining original source metadata separately. CrossfadeRingProducer supplies the existing C consumer ring and derives audible identity from consumed frames, promoting the incoming source only after the overlap ends. Live AUHAL/queue integration, output rebuilding, consistent gain across successive transitions and user opt-in are implemented in build 240. Channel-layout conversion remains pending. The untouched gapless playback path remains the default.
4. Opt-in UI and sandboxed live smoke validation: implemented in build 240. Broader listening/loopback validation remains pending. Gapless and untouched PCM remain available; processed playback is labeled explicitly.
5. Optional pitch-preserving tempo matching: separate future work.

## Analysis limits

This first analyzer is an energy/autocorrelation baseline, not a validated general-purpose music beat tracker. Its rhythm-strength score is a periodicity heuristic, not a probability. Half/double tempo, changing tempo, sparse percussion, syncopation, and dense music can mislead it. It does not detect downbeats, time signatures, phrase boundaries, key, or vocals. Do not use it alone to turn on automatic transitions. Evaluate a real-song corpus and detection confidence policies before enabling the planner. No external analysis library or network service is used.

## Initial validation

Synthetic onset tests cover 60/90/120/150/180 BPM with count, timing and ordering assertions. Native PCM click-track tests exercise decode, energy bins, persistent cache reuse, file-change invalidation, cancellation, and time budget handling. Silence, constant envelopes, malformed input and deterministic nonperiodic noise must not invent tempo. These tests do not establish real-music accuracy or audible transition quality. Playback behavior has not been changed by this stage.

## Planner validation

14 planner/rhythm tests pass, including differing beat phases, requested 4/8/16-beat windows, shorter overlaps for tempo drift, half/double tempo rejection, missing/weak analysis, malformed/stale profiles, sparse/irregular beats, late scheduling, and gapless album protection. The package builds with the preview UI. The preview has not been exercised in an installed app; listening and sample-accurate mixing tests belong to the next stage.

## PCM mixer validation

13 crossfade/gapless tests pass: sample output across 1/3/7/4096-frame block sizes, short decoder reads, fully correlated full-scale sources, fade/dry endpoint continuity, seeks in each phase, early source failure and reset, aliased-decoder rejection, incompatible rates, output-buffer validation, packed 24-bit conversion, and NaN/infinity safety. The mixer has not been connected to AUHAL or listening-tested. Equal-power dry gain must be maintained across a whole playback mode/session; enabling it only at the final seconds would cause an audible level step. Do not expose the mode until this is integrated and validated.

## Conversion and ring bridge validation

17 conversion/crossfade/gapless tests pass. Conversion tests cover 44.1/48/96 kHz pairs, stereo channel polarity, 440 Hz phase/fidelity, duration, chunk-size-independent results, restart, bounded-preroll seeking through EOF, and decoder errors. Normal converter priming compensates filter latency; a nonzero seek rounds the preroll anchor up to avoid requesting a nonexistent final output frame. Seeking in this processed path can differ by a fractional source/output frame and does not claim bit-perfect equivalence. The callback input box is private and confined to synchronous conversion on the same producer worker.

Mixed-rate C ring tests cover wraparound, complete sample equality against the direct mixer, no premature identity promotion while decoding ahead, overlap/promotion source timing, seek reset, EOF drain, and zero underrun counts in controlled non-starving reads. This is not a hardware playback or listening test. The default installed playback path still uses GaplessPCM. Neither a user-facing crossfade setting nor the AUHAL session switch has been enabled yet.

## Live opt-in integration — build 240

Settings → Playback now exposes Smart Crossfade, off by default. It is persisted per app and applies on the next source open. The app and Settings share one Player instance. Processed sessions use Float32 at the outgoing session rate; every dry and mixed segment keeps the same equal-power headroom. Original source metadata is retained separately, and expanded Now Playing labels the mode as processed audio. The untouched mode remains the default.

Player first installs a gapless successor, then optionally analyzes the pair and asks the engine to prepare a transition. Same-album neighbors and repeated copies of the same source conservatively stay gapless. Optional analysis/preparation failure or a missed buffered boundary leaves the gapless successor intact. Utility-side preparation opens independent, security-scoped source decoders; a request revision and playback token prevent obsolete work from being installed. The existing C render callback remains unchanged.

GaplessPCM caps the outgoing producer at the selected fade start, emits the prepared mixed tail, then promotes the incoming segment when its overlap has actually been consumed. The incoming displayed position therefore starts at its already-played overlap duration. Queue edits do not cut off an overlap that is already audible; the existing staged-entry adoption keeps that song identifiable at promotion. Explicit seeking discards the transition and reconstructs the audible source. Output selection/recovery retains the processed-session choice and rebuilds/reprepares from the audible source position.

Validation: 387 tests across 56 suites passed. New tests cover mode persistence and next-open behavior, same-album/repeat protection, actual mixed-rate GaplessPCM overlap, consumed-frame identity promotion, post-promotion seeking, preparation cancellation and late-install fallback. Existing queue, PCM, conversion and recovery regressions remain passing. A locally signed sandboxed QA release played two quiet 12-second stereo ALAC fixtures at 44.1 and 48 kHz with Smart Crossfade enabled; the second song appeared at about 5.42 seconds with a 44.1 kHz float output, confirming the incoming overlap had already played. No visible stop/error occurred. Paused Reconnect Output and a seek to five seconds also succeeded afterward.

Limits: this is not a listening-quality certification or loopback recording. Physical unplug/replug, actual sleep/wake, Bluetooth changes and other DACs were not exercised in this smoke test. Different channel counts/layouts still fall back rather than being remapped. Channel-layout conversion, pitch-preserving tempo matching, vocal/phrase detection and broader real-song analysis evaluation remain future work. The heuristic beat tracker can misestimate tempo; confidence filtering and conservative gapless fallback remain necessary.

## Transition length — build 241

Settings → Playback adds Short (4 beats), Balanced (8 beats, the default), and Long (16 beats). The preference persists independently of the opt-in toggle; unknown stored values fall back to Balanced. These are preferred beat windows, not fixed seconds. The planner retains its 2–12 second bounds, drift checks, short uncertain-rhythm fallback, and same-album gapless protection. Changing length invalidates pending planning and prepares the next transition again; an overlap already audible remains committed by the engine.

Validation: all 389 tests across 56 suites pass. Preference tests cover defaults, invalid stored values, all three persisted choices and independence from enabling processing. A queue regression verifies length changes reprepare the same successor without reopening playback or breaking same-album protection. Existing parameterized planner tests exercise 4/8/16-beat requests and shorter overlaps when tempos drift. No tempo stretching is introduced.

## Now Playing controls and preview parity — build 242

Expanded Now Playing adds a waveform button for compact transition controls. The popover shares the persisted opt-in and 4/8/16-beat picker with Settings, and reports whether the current session uses processed or untouched audio. Adjusting preferences does not reopen or seek the current song.

Get Info's transition preview now follows the actual automatic successor, including Repeat One and Repeat All wrapping. It uses the selected beat window and the same conservative repeated-file/same-album protection as live playback. Changes to repeat mode, the successor, or preferred length invalidate an existing preview. Preview remains analysis-only and does not promise that a future transition will be installed before its buffering deadline.

Build 242 validation: all 390 tests across 56 suites pass. New queue coverage checks Repeat One, Repeat All wrapping from the final queue entry, end-of-queue with repeat off, same-album preservation and repeated-file preservation. Existing 4/8/16-beat planner tests remain passing.

## Mono/stereo continuity — build 243

Opt-in processed sessions now use stereo when opening a mono source. Mono samples are duplicated unchanged to left and right, before sample-rate conversion, in the converter's preallocated producer-side input buffer. There is no stereo downmix, surround upmix, inferred speaker layout, or additional render-callback work. Stereo sources retain their two distinct channels. Original source metadata still reports mono when appropriate; the client PCM reports stereo.

Successor preparation and two-source transition preparation receive the session's channel count as well as sample rate, so mono/stereo pairs can share the same stereo ring in either order. Incompatible channel conversions reject preparation and retain the existing fallback. Untouched playback does not use this mapping. The processed format remains preserved through the existing session rebuild/recovery path.

Validation: 393 tests across 56 suites pass. New tests cover mono duplication at 44.1/48 kHz, exact channel equality, source metadata, waveform fidelity, restart/chunk independence, nonzero seeks and rejected downmix/unsupported channel requests. Native mono→stereo and stereo→mono fixtures pass actual mixed-rate GaplessPCM overlap, consumed-frame source promotion, finite/bounded samples, preserved stereo polarity, post-promotion seek and controlled non-starving ring reads without underruns. These automated checks do not certify acoustic quality or physical-device recovery.
